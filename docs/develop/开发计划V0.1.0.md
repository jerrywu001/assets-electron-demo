### M8 · 分类与设备清单简化（0.5 天）

- PC/NB/MON 在界面统一为“办公电脑”，SRV/OTH 保留。
- 设备清单不包含“基础配置”组件；显示器、电源、鼠标、键盘等由设备清单手工登记。
   - 设备清单设备类型由资产分类关联数据驱动，全部手工登记。
- 采集仅保留采集记录与资产匹配，不再自动回填设备清单。

### M9 · 办公电脑配置区（0.25 天）

- 选择“办公电脑”时显示“配置信息”区块及“自动获取本机配置”按钮。
- 确认后仅回填设备名称、MAC 地址、CPU、内存、硬盘五项配置数据。
- 不向设备清单写入组件；主机、笔记本、显示器、电源、键鼠等继续手工登记。
- 取消确认不执行任何操作。

### M10 · 成色估值与一致性校验（0.5 天）

- 净值不再依赖购买日期和年折旧率，改为 `原值 × 成色 ÷ 10`，成色为整数 1-10。
- 登记/编辑时 MAC 忽略大小写及分隔符进行唯一校验，重复时 toast 阻止提交。
- 员工列表展示“X资产共N设备”；空设备清单资产至少计为 1 台，避免出现“有资产但 0 设备”。
- 品牌型号、序列号 SN 从资产基础信息移至设备清单行管理；既有资产的首行设备在编辑、详情和设备总览中自动回填历史 SN，兼容旧数据。

### M11 · 资产分类与设备类型管理（1 天）

- 新增资产分类管理：预置分类不可删除/改名/value 不可变；自定义分类可新增、删除、改名，value 创建后不可修改。
- 新增设备类型管理：预置设备类型含主机、笔记本、显示器、电源、键鼠套装、其他；将“其他外设”改名为“其他”。
- 建立资产分类与设备类型的关联维护；资产登记和设备清单下拉按关联关系过滤。
- 登记页禁止使用静态设备类型字典，必须按当前资产分类读取关联数据；预置分类初始化默认关联办公电脑的主机/笔记本/显示器/电源/键鼠套装/其他，服务器和其他关联其他。
- 验证分类关联修改后登记页下拉立即反映，未关联设备类型不得出现。
- 无关联设备类型时，登记页隐藏新增按钮和表格，显示空状态与跳转按钮；跳转资产分类管理后自动打开对应分类抽屉。
- 删除有资产关联的自定义分类时拒绝，并提供迁移提示；补充数据库、IPC、前端和冒烟验收。

### M7 · PC/NB 配置信息区与基础配置收敛（0.5 天）

1. **表单交互调整**（0.2d）
   - PC/NB 才显示“配置信息”区块和“自动获取本机配置”按钮；区块包含设备名称、MAC 地址和基础配置。
   - 界面将 hostname 字段文案统一为“设备名称”；MAC 地址仅 PC/NB 显示，其他分类隐藏且不提交。
   - 点击先弹确认框“请确保要登记的设备就是当前设备”；取消不触发 IPC 且不改值。
2. **采集回填规则调整**（0.2d）
   - 采集并回填设备名称、MAC 地址，以及 CPU、内存、硬盘规格参数。
   - CPU/内存/硬盘/主机四类组件统一映射为“基础配置”行；重复获取覆盖该行，不追加重复行或网卡行。
3. **回归验证**（0.1d）
   - 覆盖 PC、NB 与 MON/SRV/OTH 分类显示差异，以及确定/取消两个分支。

- 资产编号 `IT-{分类}-{年}-{4位序号}`：事务内 `SELECT ... FOR UPDATE` + 唯一索引兜底
- 净值 shared 纯函数，前端预览与主进程查询同源；净值应用层现算不落库

### 计划外新增 1：IPC 端到端测试与 Proxy 克隆 bug 修复
- **真实 bug**：页面把 Vue `reactive()` 的 query/form 直接传给 IPC，Proxy 在 contextBridge 边界结构化克隆时抛 `An object could not be cloned`
- **修复**：净化必须发生在页面主世界（进桥之前）——`useElectron()` composable 统一包装，参数先 JSON 深拷贝；preload 保留第二道防线
- **自测基建**：`npm run ipc-test`（隐藏窗口 + 真实 preload 的端到端测试，故意用 Proxy 验证修复）

### 计划外新增 2：M6 · UI 升级（Tailwind CSS 4 + 双主题）
- 接入 Tailwind 4（`@tailwindcss/vite`），视觉对齐 Next.js/Vercel 官网风
- **语义化 CSS 变量双主题**：颜色全部走 `var(--app-*)`，`:root` 定义亮色、`html.dark` 定义暗色；Tailwind 经 `@theme inline` 映射工具类（`bg-app-surface` 等），切主题只是 toggle 一个 class
- Element Plus 接入官方暗色变量包（`dark/css-vars.css`），自定义组件覆盖也全部改走语义变量
- 侧栏可收起（224px ↔ 56px，localStorage 持久化）+ 暗色切换按钮（持久化）
- 新增 `npm run shot`（`--shot --page=xxx`）：隐藏窗口加载真实界面截图，用于 UI 自检
- 坑记录：自定义 `:root` 变量必须放在 EP 样式之后导入，否则被默认主题覆盖

## 技术决策记录（面试可直接引用）

| 决策 | 理由 |
|---|---|
| 成色估值放 shared 层纯函数 | 前端预览、主进程查询和导出同源，杜绝多套算法漂移 |
| IPC 按业务模块拆文件 | 渠道一多就按域拆分，避免单个 ipc.ts 膨胀 |
| 组件行用独立子表而非 JSON 字段 | 组件需要行级编辑和按类型统计；JSON 适合"只读快照"（如采集原始数据），不适合结构化业务数据 |
| 员工/资产不物理删除 | 台账系统审计追溯优先，状态机收口 |
| vue-router hash 模式 | file:// 协议下 history 路由刷新 404 |
| IPC 参数净化放 useElectron（页面主世界） | contextBridge 边界就会结构化克隆，Proxy 净化必须在进桥之前做 |
| 成色使用 1-10 整数 | 取消依赖购买日期的折旧推算，以登记时可理解、可直接维护的设备成色估值 |
| 主题走语义变量 var(--app-*) + @theme inline | 切主题只 toggle html.dark，Tailwind 工具类与 EP 覆盖样式同源联动，零 JS 改样式 |

## 风险与对策

| 风险 | 对策 |
|---|---|
| 表单+动态行工作量超预期 | M2 是最大里程碑，先做 PC 类跑通再扩分类 |
| 净值"现算"在列表大数据量时慢 | 1000 条内应用层算没问题；超量再考虑加缓存列 |
| 采集匹配规则误判（换网卡/改名） | hostname+MAC 双因子，人工可在详情页手工绑定 |
