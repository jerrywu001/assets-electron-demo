# 资产台账管理系统 · 产品需求文档（PRD）

| 文档信息 | |
|---|---|
| 版本 | v1.1 |
| 日期 | 2026-08-15 |
| 现状基线 | 已有：本机信息采集 → MySQL 入库 → Excel 导出 → 水印/打印/下载管控/审计 |
| 本版目标 | 从"单机采集工具"升级为"IT 资产台账管理系统" |

---

## 1. 背景与目标

### 1.1 业务背景
公司 IT 部门需要管理数百台办公设备。现状痛点：
- 资产信息靠 Excel 人工登记，配置信息靠人肉开箱查看，错漏多
- 员工入职/离职/转岗时设备交接无记录，资产去向说不清
- 资产价值状态缺少统一记录，盘点时对不上账

### 1.2 产品目标
1. **台账化**：每台资产有唯一编号、完整档案（配置 + 归属 + 价值）
2. **采集自动化**：硬件配置由客户端自动提取，登记时一键填充，避免手填错误
3. **生命周期可追踪**：资产绑定员工，覆盖 在用 / 闲置 / 维修 / 报废 状态，离职自动触发回收流程
4. **价值可计算**：按原值和成色自动算当前净值，支撑盘点与价值对账

### 1.3 用户角色
| 角色 | 诉求 |
|---|---|
| IT 管理员（主要用户） | 登记资产、分配设备、盘点、导出台账 |
| 员工（被采集端） | 无感——客户端自动上报本机配置 |
| 财务（数据消费方） | 拿导出的 Excel 做价值对账 |

## 2. 核心业务概念

### 2.1 资产 = 主机档案 + 设备清单
一台"资产"（如某员工的一套办公电脑）由两部分组成：
- **资产档案**：编号、分类、归属人、状态、原值、成色
- **设备清单（组件）**：这台资产包含哪些物理部件，行式结构：

| 设备类型 | 示例 |
|---|---|
| 主机 | 品牌机/组装机，序列号 |
| 主机/笔记本 | 办公电脑的设备清单组件，手工登记 |
| 显示器 | Dell U2720D ×2（手工登记） |
| 电源 | 650W（手工登记） |
| 键鼠套装 | Logitech MK470（手工登记） |
| 其他 | 扩展坞 / 耳机 / 摄像头… |

> 设计要点：办公电脑的自动获取只回填配置信息区的设备名称、MAC 地址、CPU、内存、硬盘；不新增或修改设备清单行。

### 2.2 资产编号规则
`IT-{分类码}-{年份}-{4位序号}`，例：`IT-PC-2026-0037`
分类码：PC 台式机 / NB 笔记本 / MON 显示器 / SRV 服务器 / OTH 其他

### 2.3 资产状态机

```
        登记            分配给员工          归还
  (无) ────→ 闲置 ──────────→ 在用 ──────────→ 闲置
                              │  ↕ 报修/修好
                              ↓  报废审批
                             维修中          报废（终态）
```
- **离职联动**：员工标记离职时，其名下"在用"资产自动转入"待回收"清单（闲置的子状态），IT 确认回收后转"闲置"
- 报废为终态，不可回退

### 2.4 价值规则
- 不再根据购买日期或折旧年限计算价值，不展示、填写或存储购买日期和年折旧率。
- 成色为整数 `1-10`，`10` 表示全新、`1` 表示成色最低；默认值为 `10`，可按单台资产调整。
- 当前净值：`原值 × 成色 / 10`，保留两位小数；原值或成色修改后实时更新。

## 3. 功能需求（按模块）

> 资产分类由预置分类和自定义分类组成。预置分类不可删除、改名或修改 value；自定义分类允许新增、删除、改名，但 value 一经创建不可修改。设备清单字段统一称为“设备类型”，并按资产分类关联可选项。

### 3.1 员工管理
**页面：员工列表 + 新增/编辑弹窗**

| 字段 | 类型 | 约束 |
|---|---|---|
| 工号 | 文本 | 必填，唯一 |
| 姓名 | 文本 | 必填 |
| 部门 | 下拉树选择 | 必填，数据来自部门树（§3.2），仅允许挂靠叶子部门；公司根节点和有下级的中间节点不可选；列表展示完整路径如"研发中心/前端组" |
| 职位 | 文本 | 选填 |
| 入职日期 | 日期 | 选填 |
| 在职状态 | 在职 / 已离职 | 必填，默认在职 |
| 离职日期 | 日期 | 离职时必填 |

**业务规则**：
- R1：标记"已离职"时，系统检查该员工名下"在用"资产，弹窗列出并提示"回收后资产将转为待回收"
- R2：已离职员工不可被分配新资产；历史记录保留（软删除思路，不物理删）
- R3：员工列表显示“X 资产共 N 设备”。X 为名下未报废资产档案数；N 按每项资产的设备清单数量统计，空清单资产至少计为 1 台，可点击下钻

### 3.2 组织架构（部门树）
**页面：左侧部门树 + 右侧部门信息/员工面板**

- **树形结构**：`parent_id` 自关联，支持无限层级（公司 → 部门 → 小组），如：
  ```
  某某科技有限公司
  ├── 研发中心
  │   ├── 前端组
  │   ├── 后端组
  │   └── 测试组
  ├── 产品部
  └── 人事行政部
  ```
- **操作**：树上增/删/改节点、拖拽调整层级（拖拽做不了的版本可先提供"更换上级"下拉）
- **删除保护**（两条都满足才允许删）：
  - R7：有子部门的节点不允许删除
  - R8：节点（含所有子孙部门）下有员工时不允许删除
- **员工挂靠**：员工可挂在任意层级节点（不一定要叶子），员工的"所属部门"展示为完整路径（如 研发中心/前端组）
- **种子数据**：1 个公司根节点 + 上述示例两级结构
- 选中树节点时右侧显示：部门信息（名称/备注/人数统计）+ 该部门（含子部门）员工列表

### 3.2.1 资产分类管理

**页面：资产分类管理**

- 展示预置资产分类和自定义资产分类。
- 预置分类：办公电脑（value `PC`）、服务器（value `SRV`）、其他（value `OTH`）；预置分类不可删除、改名或修改 value。
- 自定义分类：可新增、删除、改名；value 创建时生成并永久保持不变，不提供 value 编辑。
- 删除自定义分类前检查是否有关联资产；有关联资产时禁止删除，并提示先迁移资产。
- 每个资产分类配置其可选设备类型；分类表单中可新增/移除关联设备类型，但不能删除设备类型本身。
- 资产登记表的“资产分类”下拉和“设备类型”下拉均读取管理数据；分类切换后，设备类型只显示该分类已关联的选项。
- 登记页不得使用静态设备类型字典或显示未关联类型；设备类型下拉必须按当前资产分类实时读取 `category_device_types` 关联结果。
- 当前资产分类没有关联设备类型时，登记页隐藏“新增行”按钮和设备清单表格，显示空状态提示“当前资产分类尚未关联设备类型”，并提供跳转资产分类管理的按钮；跳转需自动打开对应分类的右侧配置抽屉。
- 预置分类默认关联：办公电脑关联主机、笔记本、显示器、电源、键鼠套装、其他；服务器和其他默认关联其他。分类管理保存后，登记页下次加载立即生效。

### 3.3 资产登记（核心表单）
**页面：登记表单（新增/编辑共用）**

**A 区 · 基本信息**
| 字段 | 控件 | 说明 |
|---|---|---|
| 资产编号 | 文本 | 新增时按规则自动生成（可改），唯一 |
| 资产分类 | 下拉 | 来自资产分类管理，决定可选设备类型 |
| 归属员工 | 下拉（搜索） | 只显示在职员工；选了即"在用"，不选为"闲置" |
| 状态 | 下拉 | 在用/闲置/维修中/报废，联动归属员工 |
| 存放位置 | 文本 | 如 "3F-A区-012" |

**B 区 · 价值信息**
| 字段 | 控件 | 说明 |
|---|---|---|
| 原值（元） | 数字 | 采购价 |
| 成色 | 整数 1-10 | 默认 10；`10` 为全新、`1` 为成色最低 |
| 当前净值 | **只读** | 原值 × 成色 / 10，随原值、成色实时计算显示 |

**配置信息（仅资产分类为办公电脑时显示）**
- 提供“自动获取本机配置”按钮。
- 点击按钮先弹出确认框：“请确保要登记的设备就是当前设备”。
- 配置信息字段包括：设备名称、MAC 地址、CPU、内存、硬盘。
- 点击“确定”：调用 IPC 获取并回填上述五项信息，不新增或修改设备清单行。
- 点击“取消”：不执行任何操作，保持表单原值不变。
- MAC 地址字段仅在资产分类为办公电脑时显示；切换为其他分类时隐藏，并不参与提交。

**设备清单（动态行）**
- 表格内编辑：设备类型（下拉）/ 品牌型号 / 序列号 SN / 规格参数 / 数量 / 备注
- 行操作：新增、删除、上移下移
- 设备类型由资产分类管理维护关联关系；登记页只展示当前资产分类已关联的设备类型。预置设备类型包括主机、笔记本、显示器、电源、键鼠套装、其他，全部手工登记，不含“基础配置”。“其他外设”统一改名为“其他”。

**备注**：多行文本

**校验规则**：
- R4：资产编号唯一；状态为"在用"时归属员工必填
- R5：净值计算在前端实时预览，主进程查询和导出时按原值、成色重算，结果以同一 shared 纯函数为准
- R6：报废需二次确认弹窗（"报废后不可恢复"）
- R7：登记或编辑时，MAC 地址忽略大小写、冒号和短横线格式差异进行唯一性校验；重复 MAC 阻止提交并 toast 提示已登记的资产编号

### 3.4 资产台账（列表页）
- 列：编号 / 分类 / 归属员工（部门）/ 状态 / 原值 / 成色 / **当前净值（自动算）** / 最近盘点时间
- 筛选：分类、状态、部门、关键词（编号/型号/SN 模糊）
- 行操作：查看详情（抽屉，含设备清单）/ 编辑 / 变更归属 / 报废
- 顶部统计卡片：资产总数 / 在用 / 闲置 / 维修 / 账面总净值
- 「导出台账 Excel」：弹"另存为"对话框（沿用现有实现），导出当前筛选结果

### 3.5 设备总览（全局组件视图）
**页面：跨资产的设备平铺列表**

- 数据源：`asset_components` 平铺，每行 = 一个物理部件
- 列：设备类型 / 品牌型号 / 序列号 SN / 规格参数 / 数量 / 来源（自动/手工角标）/ **所属资产编号** / **归属员工（部门）** / 资产状态
- 筛选：设备类型（显示器/电源/主机/CPU/内存/硬盘/键鼠/外设）、来源（自动/手工）、关键词
- 典型用途（面试也能讲）：
- "全公司有多少台显示器？分别在谁手上？" → 筛设备类型 = 显示器
  - "哪些机器是自动采集过配置的？" → 筛来源 = 自动
- 行点击 → 跳转所属资产的详情抽屉（与台账页复用同一组件）
- 只读视图，不提供在此页编辑（编辑回资产登记表单，单一数据源入口）

### 3.6 本机采集上报（沿用 + 增强）
- 保留现有"一键采集"：本机配置 → MySQL
- 增强：采集结果自动关联到"本机对应资产"（按 hostname + MAC 匹配资产档案），更新其设备清单中的"（自动）"行
- 匹配不到资产时提示"本机未登记，请联系 IT 登记"

### 3.7 审计与管控（沿用现有）
- 所有写操作（增删改资产/员工/部门、导出、报废）记 audits 表：操作人、动作、详情、时间
- 屏幕水印、打印拦截、下载拦截保持开启
- 新增：导出动作审计中记录导出条数和筛选条件
- 审计日志动作列展示中文名称，英文 action 仅作为内部枚举值；筛选栏提供动作下拉（位于关键词输入前）和关键词过滤。动作目录覆盖资产、员工、部门、资产分类、设备类型、分类关联配置、本机配置获取、导出和安全拦截。

### 3.8 仪表盘
- 顶部指标：资产总数、在用资产、待回收、低成色资产（成色 1-5）、账面总净值。
- 资产状态以柱状图、资产分类以环形图、成色以柱状分布图展示，可下钻到对应资产台账筛选结果。
- 展示低成色关注清单和最近登记资产，点击“查看”跳转到对应资产。
- 看板刷新时重新读取资产、分类和统计数据；使用 ECharts 渲染图表并适配窗口缩放与深色主题。

## 4. 数据模型（MySQL）

```sql
departments   (id, name, parent_id FK NULL, remark, sort, created_at)
employees     (id, emp_no UNIQUE, name, dept_id FK, position,
               hire_date, status ENUM('active','left'), leave_date, created_at)
asset_categories (id, value UNIQUE, name, is_preset, created_at)
device_types    (id, value UNIQUE, name, is_preset, created_at)
category_device_types (category_id FK, device_type_id FK,
                       PRIMARY KEY (category_id, device_type_id))
assets        (id, asset_no UNIQUE, category,
               employee_id FK NULL, device_name, mac_address,
               status ENUM('idle','inuse','repair','pending_recycle','scrapped'),
               location, original_value DECIMAL(10,2), condition_score TINYINT,
               remark, created_at, updated_at)
asset_components (id, asset_id FK, device_type, brand_model, sn, spec, quantity,
               source ENUM('auto','manual'), remark)
audits        (id, action, detail, at)   -- 沿用现有
```

- 部门树：`departments.parent_id` 自关联，`NULL` = 公司根节点；`sort` 控制同级排序
- 员工删除 = 标记（不允许物理删除有资产关联的员工）
- 资产删除：本版不提供物理删除，用"报废"代替
- `asset_components.asset_id` 外键 + `ON DELETE CASCADE`

```

```

## 6. 非功能需求

| 项 | 要求 |
|---|---|
| 安全基线 | contextIsolation / sandbox / CSP / 最小权限 preload 全部沿用 |
| 性能 | 台账 1000 条内列表不卡（分页或虚拟滚动超量再说） |
| 数据 | MySQL 集中存储；连接配置 db.config.json 不入库 git |
| 兼容 | Windows 10/11、macOS、Linux；本机配置采集支持三端 |
| 打包 | electron-builder NSIS + autoUpdater 配置沿用 |

## 7. 非目标（本版不做）

- 服务端 Web 后台（本系统是"客户端直连 MySQL"的内网工具形态）
- 权限体系 / 登录（内网单机版，水印先写死；SSO 属二期）
- 采购流程、维修工单流转（只记录状态）
- 移动端
