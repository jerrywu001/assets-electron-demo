# 架构说明

## 技术栈

- Electron 37
- Vue 3、Vue Router、Element Plus、TypeScript
- electron-vite、Vite
- MySQL 8、mysql2
- ECharts、ExcelJS、electron-builder

## 进程与模块

```text
.codex/          Codex 工作区配置与 MCP 定义
.claude/         Claude 命令；本机设置不入库
.agents/         可复用代理技能
.husky/          Git 提交钩子
.vscode/          推荐扩展与编辑器配置
docs/            产品、开发、架构与运维说明
scripts/         数据清理与演示数据注入
src/main/       主进程：窗口、IPC、数据库访问、采集、导出
src/preload/    contextBridge：向渲染进程暴露类型化 API
src/renderer/   渲染进程：Vue 页面、组件、路由和样式
src/shared/     共享实体、IPC 契约、枚举与纯计算逻辑
```

渲染进程通过 `src/renderer/src/composables/useElectron.ts` 调用 preload API；主进程在 `src/main/ipc/` 注册处理器，并在 `src/main/db/` 完成 MySQL 数据访问。共享类型与 IPC 渠道定义位于 `src/shared/`，避免两端接口漂移。

## 工程校验

统一入口：

```powershell
pnpm run check
```

该命令按顺序执行以下检查：

- `pnpm run typecheck`：使用 TypeScript 执行 `tsc --noEmit`。
- `pnpm run lint`：使用 ESLint 校验 TypeScript、Vue 和脚本文件；Vue 的 `<style>` 标签必须独占行。
- `pnpm run stylelint`：校验 CSS 与 Vue 样式块。规则要求两空格缩进、选择器与 `{` 间保留空格、`{` 后换行、每行一条声明，以及声明尾分号。

`.vscode/extensions.json` 推荐 Volar、ESLint 和 Stylelint 扩展；`.vscode/settings.json` 固定两空格、LF 换行，并在显式保存操作时提供 ESLint 和 Stylelint 修复。

开发环境的 `ELECTRON_OPEN_DEVTOOLS` 位于 `.env.development`，设为 `true` 时启动窗口自动打开 DevTools；默认 `false`。个人覆盖可写入 `.env.development.local`，该文件不提交。

## 提交规范

Husky 在 Git 提交时执行：

- `.husky/pre-commit`：运行 `pnpm run check`，校验失败则拒绝提交。
- `.husky/commit-msg`：运行 Commitlint，校验提交说明。

`commitlint.config.cjs` 基于 Conventional Commits，允许 `feat`、`fix`、`docs`、`style`、`refactor`、`test`、`build`、`ci`、`chore` 和 `revert` 类型；提交标题最大 100 个字符。

## AI 与 MCP 配置

- `AGENTS.md`：仓库级协作规范。定义项目结构、版本化文档同步规则、pnpm 命令、测试要求、提交约定与数据库凭据保护要求，供人工和编码代理共同遵循。
- `.codex/config.toml`：Codex 工作区配置，启用 hooks、并发代理限制，并声明 Chrome DevTools MCP 服务。
- `.mcp.json`：项目级 Chrome DevTools MCP 配置，通过 `npx chrome-devtools-mcp --autoConnect` 启动。
- `.claude/commands/git-push.md`：Claude 的受控提交推送命令说明。
- `.claude/settings.local.json`：本机 Claude 设置，已被 Git 忽略，不应提交。
- `.agents/skills/git-push/`：供代理复用的 Git 提交与推送工作流。

## 构建产物

- `out/main/`：主进程构建结果
- `out/preload/`：preload 构建结果
- `out/renderer/`：Vue 渲染进程构建结果
- `release/`：打包产物；Windows 生成 NSIS 安装包，macOS 生成 DMG 与 ZIP 安装包，Linux 当前保留可执行构建流程

打包命令：

- `pnpm run dist`：使用 electron-builder 构建当前平台的默认安装包。
- `pnpm run dist:mac`：在 macOS 上显式构建 DMG 与 ZIP 安装包。

macOS 安装包的签名与公证依赖构建机上的 Apple Developer 证书和公证凭据；未配置凭据时仍可生成未签名安装包。

上述目录均为构建产物，不提交到 Git。

## 安全边界

Electron 保持 `contextIsolation`、sandbox 和禁用 `nodeIntegration`。渲染进程不直接访问 Node.js 或数据库，只能通过受类型约束的 preload API 发起业务请求。开发模式从项目根目录读取 `db.config.json`；打包应用从 Electron 用户数据目录读取该文件，也支持通过 `ASSET_DB_CONFIG` 指定绝对路径。数据库凭据不进入 `app.asar`，并被 Git 忽略。

## 安装后的 macOS 应用，配置数据库连接

在 `db.config.json` 填写 MySQL 地址、账号和密码。开发模式从项目根目录读取该文件；安装后的 macOS 应用从 Electron 用户数据目录读取（首次启动失败提示中会显示准确路径）。
也可以通过 `ASSET_DB_CONFIG` 指定配置文件的绝对路径。首次启动会自动创建数据库和业务表；该文件包含凭据，不会提交到 Git。

安装后的 macOS 应用可使用以下命令准备配置文件：

```sh
cd "$HOME/Library/Application Support/asset-inventory-client"

cp ./db.config.example.json db.config.json

# 编辑配置文件, 填写 MySQL 地址、账号和密码
open db.config.json

# 保存配置文件, 退出编辑器, 重启应用
```

## 安装后的 Windows 应用，配置数据库连接

- 推荐在 Windows 应用中配置数据库连接。

将 `db.config.json` 复制到 `C:\Users\<用户名>\AppData\Roaming\asset-inventory-client` 目录下。然后重启应用。

- 不推荐在 Windows 应用中指定 `ASSET_DB_CONFIG` 环境变量。只是临时的配置，重启应用后会失效。

Windows PowerShell 也可以通过 `ASSET_DB_CONFIG` 指定其他配置文件，并从同一终端启动应用：

```powershell
$env:ASSET_DB_CONFIG = "C:\path\to\db.config.json"
& "C:\Program Files\资产台账管理系统\资产台账管理系统.exe"
```
